# Get/set inconsistency for fractional array indices

Reading and writing an array at a fractional index disagree:

```
$ jq -n '[1,2,3] | .[1.5]'        -> null
$ jq -n '[1,2,3] | .[1.5] = 42'   -> [1,42,3]
```

Expected: a fractional index rounds down, for reads and writes alike. A slice with fractional bounds rounds its start down and its end up.

- Reads: `[range(10)] | [.[1.1], .[1.5], .[1.7]]` -> `[1,1,1]`
- Writes: `[range(5)] | .[1.1] = 5` -> `[0,5,2,3,4]`
- Slices: `[range(10)] | .[1.2:3.5]`, `.[1.5:3.5]` and `.[1.7:3.5]` -> `[1,2,3]`
- Out-of-range bounds are clamped, even very large ones: `[range(10)] | .[1.7:4294967295]` -> `[1,2,3,4,5,6,7,8,9]`; `.[1.7:-4294967296]` -> `[]`
- NaN:
  - As a slice start it means 0: `[range(3)] | .[nan:1]` -> `[0]`.
  - As a slice end it means the length: `.[1:nan]` -> `[1,2]`.
  - Reading `.[nan]` -> `null`.
  - Writing `.[nan] = 9` fails with `Cannot set array element at NaN index`.
- Slice assignment uses the same rounding: `[range(10)] | .[1.5:3.5] = ["xyz"]` -> `[0,"xyz",4,5,6,7,8,9]`
- Unchanged: `"foobar" | .[1.5:3.5] = "xyz"` still fails with `Cannot update string slices`, and `"foobar" | .[1.5]` with `Cannot index string with number`.
